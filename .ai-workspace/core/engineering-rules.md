# 全局工程规范（Engineering Rules）

适用于所有项目的通用约束。项目级规则（`projects/*/project.md`）只能更严，不能放松本文件。

## 1. 零破坏（最高优先级）
- 默认只读。没有明确授权不得修改任何业务代码、配置、环境。
- 修改前必须先确认目标文件属于任务 scope（见 `change-policy.md`）。
- 任何「不确定是否安全」的操作：**停止并报告，请求人工确认**，不猜测、不试探。

## 2. 外科手术式修改
- 只改达成目标所必需的最少文件。禁止“顺手重构”“顺手清理”“顺手升级”。
- 改代码要像周边代码：匹配其注释密度、命名、风格、缩进。
- 不引入与任务无关的新依赖、新框架、新抽象。

## 3. 不猜测事实
- 系统事实（ROS 版本、Ubuntu、Topic、TF、参数、接口、依赖）一律以 `facts/` 为准。
- 缺失即写 `UNKNOWN` / `NEEDS_CONFIRMATION` / `TODO`，禁止填一个“看起来合理”的值。
- 无法确认某文件/命令属于 ROS1 还是 ROS2 时，必须先检查（读 package.xml / CMakeLists / 环境 / 文档）再行动。

## 4. 显式假设
- 任何推断、假设都要显式写出来，标注“假设”，并说明如何验证。
- 汇报时区分「已确认事实」与「推测」，不得把假设当事实陈述。

## 5. 验证优先
- 验证先于继续修改（见 `testing-rules.md`）。
- 测试失败即停：记录失败原因并报告，不进入无限自动修复循环。
- 不得在未运行验证的情况下声称“已完成 / 已修复 / 已通过”。

## 6. 上下文与汇报
- 引用代码用 `路径:行号`。
- 汇报结果如实：失败就说失败并附输出；跳过就说跳过；完成且已核实才说完成，不加修饰。
- 对用户或其提到的任何他人使用代词时，用 they/them（中文用「其」/「该成员」），不臆测性别。

## 7. 简单优先
- 不为“显得智能”引入 Agent 框架、RAG、向量库、网关等基础设施。
- 能用一个文件、一条命令解决的问题，不搭建子系统。
