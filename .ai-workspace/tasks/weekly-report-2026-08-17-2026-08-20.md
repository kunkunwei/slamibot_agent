# D360 本周工作总结

**汇报周期：2026年8月17日—2026年8月20日**  
**项目：SLAMIBot D360 / Scout mini 2D 导航 / Go2 3D 导航**

## 一、本周总体结论

本周主要围绕 D360 设备盘点、2D 导航前后端 rosbridge 联调、地图数据清理与地图显示恢复展开。当前 WEB 和 APP 已能够正常显示 2D 栅格地图，双 rosbridge 端口职责已明确，`test_map` 及其关联数据已按授权完成清理。热点网络下导航存在偶发卡顿现象，仍需后续专项定位。新更换 BOX 上的 R1 麦克风目前未被 Jetson USB 识别，已暂停，等待硬件同事处理。

## 二、本周完成工作

### 1. D360 板端和项目现状盘点

- 完成 Jetson 板端运行服务、容器、网络和 ROS 话题的只读盘点。
- 梳理 D360 主要组成：Jetson、Livox 雷达、RTK、OAK 相机、网卡、电源模块及底层 STM32。
- 确认关键传感器话题，包括：
  - OAK 相机：`/SLB_CAM_A/compressed`、`/SLB_CAM_B/compressed`、`/SLB_CAM_C/compressed`
  - RTK：`/rtk/gga`、`/rtk/gnss`、`/rtk/raw`、`/rtk/rtcm`、`/rtk/satellites`
  - 雷达：`/livox/lidar`、`/livox/imu`
- 完成前端仓库、导航仓库及 Jetson 事实源回填，明确 ROS1 2D 与 ROS2 Go2 3D 两条产品线隔离。

### 2. 双 rosbridge 架构联调

目标是 APP/WEB 统一使用 9090，FastAPI/nav_api 内部继续使用 19090。

已完成：

- APP 默认 rosbridge 端口从 `19090` 修改为 `9090`。
- APP 修改已提交至 `codex/native-compose-filament`，提交：`3426f0a`。
- Jetson 上同时运行两套 rosbridge：
  - `9090`：面向 APP/WEB 的客户端 rosbridge，节点 `/rosbridge_websocket`
  - `19090`：FastAPI/nav_api 内部 rosbridge，节点 `/scout_nav_rosbridge`
- Nginx `/rosbridge` 反向代理最终指向 `127.0.0.1:9090`。
- FastAPI `/health` 返回 `rosbridgeConnected:true`。
- 端口 `80/5000/9090/19090` 均完成监听验证。

### 3. 2D 地图显示问题定位与恢复

问题根因：

- idle 状态没有 `/map` Publisher；进入 navigation 模式后由 `/map_server` 发布占据栅格。
- WEB 实际订阅 `/map`，但部分提示文案错误写成 `/plane_OccMap`。
- APP 使用 CBOR 解析地图数据，板端 9090 rosbridge 的 `cbor-raw` 行为与 APP 预期不一致，涉及订阅类型、消息封装和 typed array 编码三个兼容问题。

处理结果：

- 完成 WEB 提示修正及板端 rosbridge 兼容处理。
- 当前镜像：`scout-nav:map2d-topic-copy-20260820`。
- `/map` 发布者确认为 `/map_server`。
- 地图首帧约 `1157×1071`，分辨率约 `0.05`。
- WEB 和 APP 均已人工确认可以显示 2D 栅格地图。
- APP `/map` CBOR 探针通过。

遗留风险：

- 9090 rosbridge 的三处 CBOR 兼容修复目前仍属于 core 容器内 live patch，后续重建或替换 core 容器时可能丢失，需要后续固化到镜像。
