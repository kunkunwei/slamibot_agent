# ADR-0001：本地 AI 工作区采用文件化事实源，不引入 Agent 框架

- 日期：2026-08-16
- 状态：已接受

## 背景
需要为多个独立 Git 仓库（导航 ROS1/ROS2、前端、后端、部署、STM32）建立统一的 AI 开发规范与知识入口，
同时长期在本地维护，且机器人研发存在 ROS1/ROS2 双栈与“当前/迁移/未来”三套系统生命周期的强隔离需求。

## 问题
如何让 AI（Claude Code）可靠地遵守工程规范、技术栈隔离、最小权限与可回滚，而不引入额外基础设施。

## 方案
1. 用 Claude Code 原生 CLAUDE.md + `@` 导入 + 规则文件实现约束。
2. 用文件化事实源（facts/*.yaml）承载稳定事实，缺失标 UNKNOWN/NEEDS_CONFIRMATION。
3. 自定义轻量角色（Explorer/Implementer/Validator）与 Jetson 权限分级。
4. 引入 LiteLLM / RAG / 向量库 / 自研 Agent 框架。

## 选择
方案 1 + 2 + 3。

## 原因
- 复用现有 cc-switch（Claude/DeepSeek），零新增服务。
- 文件化、Git 可管理、可交接、可回滚。
- 权限模型（任务 scope + 层级）比提示词自觉更可靠。
- 简单透明，避免“为智能而增加基础设施”。

## 影响
- 优点：零依赖、可审计、可回滚、易交接。
- 代价：事实源需人工/Explorer 持续回填；规则靠 CLAUDE.md 加载，长度需控制。

## 替代方案
方案 4（自研 Agent 框架/RAG/向量库）被否决：违反“简单、文件化、本地、零额外服务”的核心诉求。
