# Context Routing Reference

## Purpose

用 HOT/WARM/COLD 分层和明确预算构造最小可用 Context Pack，使百万字项目仍能按证据工作而不全量扫描。

## Required inputs

- 当前任务、chapter_id、arc_id、出场实体、目标伏笔与所需输出。
- `novel/config.json` 中的上下文预算；若未配置，采用总计 32000 字符的保守预算。
- 当前交接、篇章计划、状态索引、摘要索引和可定位的原文路径。

## Procedure

1. 先写检索问题：本任务必须知道哪些事实、哪些认知边界、哪些未决冲突；没有问题不读取 COLD。
2. HOT 默认上限 18000 字符：任务、Chapter Contract、当前篇章目标、当前状态、活跃伏笔、最近一至两章摘要/必要正文、当前出场人物精简状态。
3. WARM 默认上限 10000 字符：当前篇章摘要、较早章节摘要、相关人物完整档案、地点、派系、物品、世界规则和跨章伏笔。
4. COLD 默认上限 4000 字符：仅检索命中的已结束篇章、退场人物、已回收伏笔、旧章节、历史讨论或废案；优先读取摘要，再读取命中原文。
5. Context Pack 按固定段落输出：作品约束、任务与合同、篇章状态、人物与认知、伏笔与债务、近期摘要、原文证据、文风约束；每段标注来源和字符数。
6. 超预算时按顺序裁剪：未命中的 COLD → 与任务无关的旧 WARM → 重复摘要 → 可由摘要替代的长原文 → 次要风格样例。不得裁掉用户约束、Chapter Contract、冲突证据和相关硬事实。
7. 若剩余信息仍超预算，拆分任务或请求明确优先级，不以全书扫描替代路由。

## Outputs

- 带 HOT/WARM/COLD 标签、来源路径和字符预算的 Context Pack。
- 被裁剪内容、缺失证据、检索命中与未命中的报告。
- 下一步需要读取的最小文件清单。

## Stop/escalate conditions

- 无法定位事实来源或索引指向缺失文件时停止并报告。
- 任务要求证明全书级否定命题时，先缩小实体、时间窗或篇章范围。
- 多个高权威证据冲突时交给 Continuity Manager，不扩大全书扫描。
- 用户要求的范围超过预算且无法安全拆分时，请用户选择优先级。
