# Model Routing Reference

## Purpose

以风险和任务价值选择精确模型、模式与调用上限，让 Luna 承担高频低风险工作，让 Sol 只处理低频高风险决策。

## Required inputs

- 任务类型、章节位置、结构影响范围、事实冲突严重度和用户质量要求。
- 已用模型调用次数、失败次数、Context Pack 大小和本地检查结果。
- 是否涉及总纲、结局、核心人物、重大关系或长期伏笔。

## Procedure

1. 固定别名：Luna = `gpt-5.6-luna`；Sol = `gpt-5.6-sol`。模型调用只能由 Codex 或其子代理执行，本地脚本不得调用模型。
2. 评分：普通明确任务 0 分；有限连续性或情绪难度 +1；关键关系转折、重大伏笔、多源冲突、高潮/卷末 +2；结局、长期主线或不可逆核心动机变化 +3；用户明确要求 Sol 直接触发。
3. 按总分选择模式：0–1 分 fast；2–3 分 balanced；4 分及以上 premium。任何高严重度矛盾、Luna 连续两次结构失败或用户明确要求均强制进入 Sol 升级审查。
4. 执行模式表：

| 模式 | Luna | Sol | 适用边界 |
|---|---:|---:|---|
| fast | 场景/上下文最多 1 次；写作或修订最多 1 次 | 0 次 | 低风险普通章 |
| balanced | 与 fast 相同 | 仅条件式审核最多 1 次 | 默认模式，有明确升级信号才调用 Sol |
| premium | Luna 用于整理、预检和可委派写作 | 由 Chief Editor 按关键节点批准 | 开篇、高潮、卷末、结局、重大反转与复杂情感节点 |

5. Sol 升级量表命中项：总纲/结局/长期主线；核心动机不可逆；重要关系关键转折；重大伏笔埋设、揭露、回收、废弃；多个事实源冲突；Luna 连续两次不达结构要求；本地高严重度冲突；用户明确要求。
6. 记录每次调用的任务、输入范围、模型、结果和是否消耗条件式 Sol 名额；禁止无差别并行多个审稿角色。

## Mandatory cost controls

1. **显式模型**：所有 `spawn_agent` 调用必须显式设置 `model: gpt-5.6-luna`。禁止省略模型字段并继承主会话模型。若需 Sol，必须显式设置 `gpt-5.6-sol`，且先满足升级与告知要求。
2. **最小上下文**：默认 `fork_context: false`。为代理提供按任务裁剪的 Context Pack，不发送完整聊天记录，不把全书、整卷或无关人物资料打包输入。
3. **普通章上限**：最多 1 次 Luna 写作代理和 1 次 Luna 审校代理；Sol 0 次。主会话能直接完成的工作不额外创建代理。
4. **禁止重复阅读**：同一批章节、大纲、人物卡和状态资料只允许一个代理完整阅读。多人并行时必须拆成互不重叠的材料或写入范围。
5. **确定性任务本地化**：CLI 校验、单元测试、格式检查、Git、索引、计数、文件查找与机械转换不得调用模型。
6. **失败复用**：代理超时、中断或漏写时，先向原代理发送最小补充指令；不得通过新代理重放完整输入。原代理确实不可恢复时才能替换，并在调用记录中写明原因。
7. **Sol 事前告知**：调用 Sol 前先向用户报告升级原因、输入文件/片段范围和预计调用次数，并取得明确同意。若用户当前请求已明确指定 Sol，可直接执行该请求范围内的调用。
8. **调用报告**：任务结束时报告实际 Luna 次数与 Sol 次数；调用日志按任务记录模型、输入范围、结果、重试及替换原因。
9. **并发限制**：默认同时运行的模型子代理最多 2 个。普通章节不得并行多个 writer 或多个 reviewer；只有任务互不重叠且并行确实节省关键路径时间时才能达到并发上限。

## Outputs

- fast、balanced 或 premium 的选择及风险分数。
- 角色到精确模型的分配、调用预算和已消费次数。
- Sol 升级理由或保持 Sol 0 次的理由。

## Stop/escalate conditions

- 普通章达到调用上限仍失败时停止，先诊断合同或上下文，不自动追加调用。
- balanced 未命中升级条件时不得调用 Sol；命中后最多 1 次条件式审核。
- premium 的额外高成本调用必须由 Chief Editor 明确批准或来自用户要求。
- 模型输出与高权威事实冲突时，以事实层级为准并转连续性裁决。
