# 流程：AIKIT 语音识别 × d360_nav2D × Go2 动作联调验证

- procedure_id: `voice-go2-integration-validation`
- target_date: 2026-08-25
- parent_task: `TASK-2026-08-21-001`
- technology: ROS1 CURRENT + 独立 Go2 控制适配（DDS/WebRTC 路径必须先确认）
- risk: 真机运动、高风险接口联调

## 目标
验证以下端到端链路，不把“识别成功”或“HTTP 200”误判为机器狗动作成功：

```text
环形麦克风 → AIKIT/run_mic.py → GET /api/voice/words
                              → POST /api/voice/intent
                              → fastapi_service/voice.py
                              → fastapi_service/dog.py
                              → Go2 WebRTC 或 DDS 驱动 → 真机动作/停止
```

## 测试前置条件（任一不满足则不进入真机动作）

1. 用户明确告知 Jetson 已开机；在此之前不得尝试 SSH。
2. 确认现场 Go2 使用 `WebRTC` 或 `DDS`，记为 `CONFIRMED`；不得同时启用两套驱动。
3. `d360_nav2D` 已存在唯一动作适配层 `fastapi_service/dog.py`，并完成真实返回码检查、动作互斥和 `StopMove()` 兜底。
4. 命令词、动作映射及安全参数已经确认；以下内容不得猜测：
   - `crouch` 是否等于 `StandDown`；
   - “蹲下”与“趴下”是否同一动作；
   - `handshake` 的真实 Go2 函数；
   - 移动速度、持续时间和转向速度。
5. 测试场地清空，机器狗周围留出安全空间；现场人员可立即物理急停或接管。
6. 核对相关仓库 `git status`、当前提交和任务范围差异，保留用户已有修改。
7. 在最后的声卡冲突专项前，只允许一个麦克风采集进程读取输入设备。

## 禁止事项

- 不执行 `docker restart/stop/start scout-nav`，不删除或重建容器。
- 不结束 Uvicorn，不执行全局 `rosnode cleanup`。
- 不把文件 copy 成功视为运行中的服务已加载新代码。
- 不混用 ROS1 Scout `/cmd_vel` 与 Go2 DDS/WebRTC 运动控制；Go2 控制不得隐式触发 ROS1→ROS2 迁移。
- 不直接采用键盘测试脚本中“持续发送且不自动停止”的移动方式。
- 未获 BUILD/DEPLOY 授权时，不编译、不重载服务、不部署。

## 分阶段测试

### T0：只读预检与代码就绪

1. 记录测试时间、代码提交、运行路径、服务端口和所选驱动（DDS/WebRTC）。
2. 只读检查现有服务/容器/ROS 节点状态，确认没有残留测试进程。
3. 检查 `GET /api/voice/words`，确认动态词表包含已批准命令词；同步检查 `run_mic.py` 本地回退词表。
4. 确认 `POST /api/voice/intent` 的失败语义：驱动未连接或派发失败时不得只返回顶层 `success=true`。
5. 若运行服务尚未加载新代码，停止测试并单独申请最小 DEPLOY 方案；不得通过重启 `scout-nav` 解决。

### T1：无真机运动的 HTTP/意图测试

1. 使用 mock 或禁用运动输出的驱动逐条提交命令词。
2. 至少覆盖：已知命令、未知命令、空文本、驱动离线、动作执行异常。
3. 核对：识别文本、意图、动作名、`dispatched`、顶层 `success`、错误信息一致。
4. 通过条件：后端不会“假成功”，未知命令不会触发任何动作。

### T2：真机静态动作

1. 先验证 `stop` 可调用且能够抢占其它动作。
2. 按一次一条命令测试已确认的静态动作，优先顺序：`stand` → `hello` → 其它已确认动作。
3. 每条命令后观察机器狗真实动作、姿态稳定性和后端返回码；动作结束后等待稳定，再执行下一条。
4. 未确认映射的 `crouch`、`handshake` 不测试。

### T3：低速、短时、可停止的移动动作

1. 速度和时长由现场用户确认后再填写，默认均为 `NEEDS_CONFIRMATION`。
2. 每个方向单独测试：前进、后退、左移、右移、左转、右转。
3. 实现必须采用“有限时长循环发送 Move → `finally` 无条件 `StopMove()`”；`stop` 必须可抢占 busy 状态。
4. 每次只执行一个短脉冲；确认已完全停止后才测试下一方向。

### T4：AIKIT 完整语音闭环

1. 只启动一个 `run_mic.py` 麦克风采集进程。
2. 确认它成功获取后端动态词表，再按 T2、T3 已通过的顺序说出命令。
3. 对每次测试记录：口述词、AIKIT 识别文本、HTTP 请求/响应、后端动作日志、机器狗实际行为。
4. 测试近音词、未注册词和环境噪声，确认不会误触发危险移动。
5. `run_mic.py` 当前未发送 `bearingDeg`；若测试“到我这里”等方位意图，必须先独立确认接口和数据来源。

### T5：声卡双进程读取冲突（最后执行）

1. 仅在 T0–T4 通过后复现两个进程同时读取声卡的问题。
2. 先记录设备名、进程、打开方式和错误日志，再评估 README 中 `dsnoop`/ALSA 配置方案。
3. 修改系统 ALSA 配置、容器设备映射或启动方式属于单独授权范围；不得为了排障顺带重启 `scout-nav`。

## 立即停止条件

出现任一情况，立即调用/触发 `StopMove()`，停止继续扩大测试并记录现场证据：

- 动作方向、姿态或持续时间与命令不符；
- 机器狗未按预期停止、出现连续动作或重复触发；
- 驱动断线、返回码异常、后端“假成功”；
- `stop` 无法抢占；
- ROS1 Scout 控制与 Go2 控制出现混发；
- 需要重启容器/Uvicorn或修改未授权系统配置才能继续。

## 验收标准

- 动态词表与本地回退词表一致，且只包含已批准命令。
- 每个已批准命令映射到唯一动作，未知/失败请求不触发动作。
- 后端响应能够区分“识别成功”“意图匹配成功”“真实派发成功”。
- 静态动作与真机表现一致；移动动作均在确认的时限内停止。
- `stop` 可抢占，异常路径无条件执行 `StopMove()`。
- 完整 ASR 链路至少完成一轮静态动作和一轮安全短脉冲移动；声卡冲突测试单独记录。
