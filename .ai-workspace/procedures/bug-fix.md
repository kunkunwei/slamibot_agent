# 流程：Bug 修复（bug-fix）

## 阶段
1. **复现与定位（Explorer）**：只读分析，确认 bug 属于哪个栈（ROS1/ROS2）、哪个仓库、哪个文件。禁止猜测根因。
2. **写任务**：记录现象、日志、复现步骤、初步假设（标注“假设”）、建议 scope。
3. **Implementer**：最小修改；改前 `git status`；不顺手重构；改后 `git diff` + 摘要。
4. **Validator**：回归验证（编译 + 相关测试 + 必要真机）；失败即停，记录并报告。

## 铁律
- 默认以 **CURRENT（ROS1 + Ubuntu 20.04）** 为目标，不触发 migration。
- 只修根因对应的最小范围；禁止“顺手”改无关代码。
- 修完必须写清：根因、改动、验证结果、回滚方式。
