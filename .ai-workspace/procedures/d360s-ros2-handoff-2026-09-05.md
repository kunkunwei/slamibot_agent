## 4. 三个入口必须分开

### 4.1 主机固化

```bash
cd ~/SLAMIBOT_D360_Framework
bash provision.bash             # 默认doctor，只读
bash provision.bash doctor
bash provision.bash apply --check-only
bash provision.bash apply --dry-run
```

只有确有缺项且用户明确允许系统写入时，才执行：

```bash
sudo -v
bash provision.bash apply
```

`provision.bash`负责：

- CH341内核模块
- `brltty`冲突
- `ttyRTK`/`ttySTM32`固定udev别名
- MID360S USB网卡NetworkManager配置

### 4.2 软件安装与构建

```bash
bash install.bash doctor
bash install.bash deps
bash install.bash build
bash install.bash install
```

`install.bash`只负责Ubuntu/ROS2/国内镜像/依赖/venv/SDK/colcon，不允许管理systemd或启动硬件。

### 4.3 硬件运行与服务

```bash
bash runtime.bash              # 默认status，只读
bash runtime.bash status
bash runtime.bash hardware-doctor
bash runtime.bash stm32-status
bash runtime.bash stm32-runapp
bash runtime.bash probe
```

systemd生命周期只能由 `runtime.bash` 管理：

```bash
bash runtime.bash generate-units
bash runtime.bash install-units
bash runtime.bash enable
bash runtime.bash disable
```

**不要把开机自启动重新塞回 `install.bash`。**

## 7. STM32与OAK FSIN

### 7.1 正确模型

```text
STM32 PA1 TIM2_CH2 10Hz -> OAK FSIN -> 三相机曝光
STM32 PB5 TIM3_CH2 1Hz  -> LiDAR同步/PPS
STM32 UART2 GPRMC       -> MID360S
Livox点云时间戳         -> ~/timeshare -> OAK ROS header.stamp
```

`timeshare`是软件时间戳，不产生物理FSIN。

### 7.2 STM32状态

串口波特率必须是：

```text
9600
```

STM32曾在开机后停在Bootloader；被动读串口无GPRMC。根据本地bootloader源码，正式BL命令 `runapp` 写 `APPRUN_FLAG_DATA=0x0000` 并跳APP。

执行后确认：

```text
GPRMC约1Hz
COG=206
固件产品版本：2.0.6（由COG推断）
PA1 10Hz FSIN恢复
```

现在使用：

```bash
bash runtime.bash stm32-status
```

应返回APP READY。只有显式恢复时才使用：

```bash
bash runtime.bash stm32-runapp
```

APP已运行时该命令幂等PASS且不发送。不要发送 `version`、未知命令、LED命令或升级命令做试探。

### 7.3 OAK验收

OAK启动过程：

```text
03e7:f63c @ 480M Bootloader
  -> 03e7:f63b @ 5000M runtime
  -> 识别CAM_A/B/C三颗AR0234
```

